# Edge Templates

Use Edge as a rendering layer, not an application layer. Load, authorize, validate, and shape data before calling `view.render()`; templates should decide how prepared data looks, not fetch or mutate it.

## Check What the Application Actually Has

Edge is preconfigured in the Hypermedia starter kit, but individual components are project files. Before using `@layout()`, `@form()`, `@field.root()`, or similar tags, inspect `resources/views/components`.

Those tags are included by the Hypermedia starter kit; they are not universal Edge built-ins. Reuse them when present. Do not invent them in a project that does not contain them, and do not add Edge or starter-kit dependencies without approval.

Follow the existing view directory structure. When creating a view, prefer the installed generator:

```bash
node ace make:view posts/index
```

This creates `resources/views/posts/index.edge`. Group views by resource instead of accumulating unrelated templates at the root.

## Render Prepared State

Render a template through the request-scoped `view` instance. Template paths are relative to `resources/views` and omit `.edge`:

```ts
import Post from '#models/post'
import type { HttpContext } from '@adonisjs/core/http'

export default class PostsController {
  async index({ request, view }: HttpContext) {
    const page = request.input('page', 1)
    const posts = await Post.query()
      .preload('author')
      .orderBy('created_at', 'desc')
      .orderBy('id', 'desc')
      .paginate(page, 20)

    return view.render('posts/index', {
      posts: posts.all(),
      pagination: posts.getMeta(),
    })
  }
}
```

Use `router.on('/').render('pages/home')` only for a genuinely static route. Once rendering needs authorization, queries, or conditional response behavior, use a controller.

Edge accepts JavaScript expressions and `await`, but that capability is not permission to query from a template:

```edge
{{-- Wrong: hidden I/O and likely N+1 work --}}
@let(comments = await post.related('comments').query())
```

Preload relationships and compute aggregates before rendering. Keep service calls, mutations, request validation, and business rules out of `.edge` files. Prefer explicit render state over reading application inputs through the global `request` object.

## Keep Template Logic Small

Use interpolation, conditionals, and loops for presentation decisions:

```edge
@if(posts.length)
  @each(post in posts)
    <article>
      <h2>{{ post.title }}</h2>
      <p>By {{ post.author.name }}</p>
    </article>
  @end
@else
  <p>No posts yet.</p>
@end
```

Move a calculation out of the template when it needs domain knowledge, is reused outside the view, or takes more than a short expression. `@let` and `@assign` are appropriate for small rendering-only values, not for rebuilding a controller inside the template.

## Escape by Default

`{{ value }}` HTML-escapes its output. Keep that default for user-controlled or database content.

`{{{ value }}}` and `html.safe(value)` bypass escaping. Use them only for HTML generated by the application or sanitized with an allowlist-based HTML sanitizer. Markdown conversion alone does not make arbitrary user input safe.

```edge
<h1>{{ post.title }}</h1>
{{{ sanitizedPostHtml }}}
```

Prepare `sanitizedPostHtml` outside the template. Never respond to a display problem by changing ordinary interpolation to raw interpolation without tracing the value's trust boundary.

## Prefer Components for Reusable UI

Use a partial for a local fragment that intentionally inherits all parent state:

```edge
@include('posts/partials/meta')
```

Use a component for reusable UI with an explicit interface. Files under `resources/views/components` become component tags and receive isolated component state through props and slots.

```edge
{{-- resources/views/components/card.edge --}}
<article {{ $props.except(['title']).merge({ class: ['card'] }).toAttrs() }}>
  <h2>{{ title }}</h2>
  {{{ await $slots.main() }}}
</article>
```

```edge
@card({ title: post.title, class: ['featured'] })
  <p>{{ post.summary }}</p>
@end
```

Use `@!card({...})` for a component with no body or slots. Prefer `$props.toAttrs()` or `$props.merge(...).toAttrs()` when a component deliberately forwards HTML attributes; remove component-only props with `except()` so they do not leak into the rendered element.

Do not turn every repeated tag into a component. Extract when the fragment has a reusable UI contract, meaningful defaults, accessibility behavior, or slots—not merely because two pages share a `<div>`.

## Build Layouts as Components

Keep shared document structure in a component and expose only the slots and props pages need:

```edge
{{-- resources/views/components/layout.edge --}}
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>{{ title || config('app.appName') }}</title>
    @vite(['resources/js/app.js'])
  </head>
  <body>
    {{{ await $slots.main() }}}
  </body>
</html>
```

```edge
@layout({ title: 'Posts' })
  <main>...</main>
@end
```

Use named slots when a layout or component has multiple intentional outlets. Use stacks only when descendants really need to contribute page-level assets; use the `*Once*` stack variants for resources that must not be duplicated.

## Use AdonisJS Helpers Instead of Reimplementing Them

- Generate application URLs with `urlFor()`. Do not hardcode paths, and do not copy the deprecated `route()` helper from older examples.
- Resolve Vite assets with `@vite` and `asset()` rather than build-output paths.
- Read configuration with `config()` rather than environment variables.
- Use `old()` and `@inputError` for flashed form state.
- Use `@can` and `@cannot` to match the UI to Bouncer decisions, while keeping the real authorization check in the controller.
- Use `t()` and `i18n` when the configured i18n package owns user-facing text or formatting.

Package-contributed helpers exist only when their package and middleware are configured. Check `package.json`, `adonisrc.ts`, `start/kernel.ts`, and sibling templates before using them.

## Protect Forms

Every state-changing server-rendered form needs CSRF protection when Shield is configured. The Hypermedia starter kit's `@form` component injects the token automatically. A plain HTML form must include `csrfField()`:

```edge
<form method="POST" action="{{ urlFor('posts.store') }}">
  {{ csrfField() }}

  <label for="title">Title</label>
  <input
    id="title"
    name="title"
    value="{{ old('title') || '' }}"
    aria-describedby="title-error"
  >

  @inputError('title')
    <div id="title-error">
      @each(message in $messages)
        <p>{{ message }}</p>
      @end
    </div>
  @end

  <button type="submit">Create post</button>
</form>
```

Do not exempt ordinary browser forms from CSRF checks to make them submit. Preserve labels, semantic controls, error associations, and keyboard behavior when wrapping form elements in components.

## Share Globals Sparingly

Register custom Edge globals from a preload only for stable, presentation-focused helpers needed across many templates. Prefer explicit render state for page data. Never register a global that hides database access, authorization, or a mutable request-specific singleton.

The framework already supplies request-scoped state such as `request`, `auth`, `session`, and flash messages when the corresponding packages and middleware are active. Do not duplicate them in custom globals.

## Test Through HTTP

Test rendered pages with Japa's API client so routing, middleware, authentication, controller state, and Edge rendering execute together. Assert the status and the small pieces of HTML or text that express the behavior; avoid snapshots of entire pages, which turn harmless markup changes into noisy failures.

Cover authenticated and unauthorized states for conditional UI, validation errors and old input for forms, empty and populated collections, and escaping when rendering user-controlled content.

Use `@dump(value)` while debugging template state in development, and remove debugging tags before committing.
